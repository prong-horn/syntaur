### Board history and project archives

There is no existing completed-age configuration. Use URL-only `history=recent|all|older` (default recent) and `olderThanDays=<integer 1..36500>` (default30; invalid values normalize to30). The Board exposes both controls; omit defaults from the URL and do not add a view-prefs field. The modes are: recent (default: active plus recent terminal), all, older (only terminal older than N). Both done and dropped count as terminal, matching spec §8.2 and SV-7. Compute age from completion/move history for the current terminal entry; reopening immediately makes the ticket active. At exactly the cutoff it is not older; missing/invalid completion dates stay visible in recent and are excluded from older. Never use an unrelated recent journal edit to reset completion age. Do not write archive flags or modify ticket files.

Board filter state is URL-authoritative on first load and history navigation, then falls back to valid existing view preferences/defaults. Changing a control updates URL and supported existing preferences deliberately (project selection and the URL-only keys below never write preferences); an async preference response must not overwrite newer user selection. Keep current project-specific preference keys (no saved-view resurrection). Selecting older overrides default terminal-age hiding, but still intersects explicit project/template/status/query filters; disclose an empty intersection. Project visibility is a separate active/archived/all facet. This facet scopes ONLY the project panel: active projects use `/api/projects`, archived projects use retained `/api/archived`, all combines them by slug. The existing `/api/tickets` board feed remains active-project-only. Selecting an archived project opens its panel and shows an explicit disclosure that its tickets are excluded from the active kanban/table; show its existing archive payload tickets read-only in that panel, without requiring board metrics/verbs. Archived projects remain discoverable and restorable even with no tickets. Restore uses the existing API and invalidates archived/project/board resources. No new archived-ticket board API is needed.


Board URL grammar (serialize via URLSearchParams, repeated keys for multi-select; legacy comma-separated status values normalize to repeats):

| Keys | Encoding and precedence | Persistence |
| --- | --- | --- |
| view | kanban or table; invalid→effective preference then existing default | existing view mode preference |
| status, template, priority, assignee, tags | repeated validated strings (known stage/priority enums; ids/tags encoded literally); remove duplicates; explicit empty key means clear, absent means inherit | existing filter fields |
| project | repeated URL-only slugs; absent or explicitly empty means all projects; deduplicate | never read or write the saved project filter, including AQL synthesis; leave any saved value untouched on disk; other filter writes deep-merge supported fields rather than replacing the stored filters object |
| stale | existing supported staleness filter enum; absent inherits preference, invalid clears | existing filter field only |
| query | full existing AQL string, encoded once; if present it is authoritative and parsed back to supported chips; otherwise synthesize AQL from URL chips over effective prefs using existing view-filters-query helpers | store supported filters in existing schema, never add an opaque query preference; preserve complex query in URL |
| sort, dir | current sort helper's supported field enum; dir asc/desc; invalid→existing default | existing sort preference |
| history, olderThanDays | modes/default/limits specified above | URL-only |
| projectVisibility | active/archived/all, default active; project-panel only | URL-only |
| panel | projects/project/dependencies, omitted normally | ephemeral URL-only |
| dialog | new-ticket/new-project/edit-project, omitted normally; edit-project requires project identity; new-ticket provides its own project selector | ephemeral URL-only |

Preference scope is `p:<slug>` only when the URL contains exactly one nonempty project slug, otherwise global/null; choose this key directly from the URL without waiting for the projects request. Scope identity does not change when active/archived lookup finishes; missing/archived projects render the specified disclosure/panel instead of reseeding filters. The global saved project filter is deliberately ignored on both read and write, including query construction, and remains untouched on disk. No URL project means all projects; this small behavior change prevents recursive preference-scope selection. Add a regression with a saved single-project filter proving it is ignored and byte-preserved; density always stays global. A project's identity is resolved from the URL before reading scope preferences. On first load, merge existing defaults→scope preferences→explicit URL fields exactly once, guarded by a navigation/user-edit generation. User changes persist only supported existing fields to that scope; browser back/forward consumes the URL without writing prefs. New project scope loads cannot overwrite newer query/control input. No storage migration or change to CLI AQL semantics. Add fixtures for commas in tags, empty vs absent filters, multi-project scope, complex query roundtrip and conflicting query/chips (query wins).

## Data, network and metrics contracts

### One finite-resource hook, explicit stateful transports

Implement a small React 18 `useSyncExternalStore` cache without a new runtime dependency. New files under `dashboard/src/data/`: `client.ts`, `cache.ts`, `resources.ts`, `useResource.ts`, `mutate.ts`, `types.ts`. Move response interfaces from `hooks/useProjects.ts` into types; no second independent fetch/cache implementation remains. Thin domain selectors/wrappers may remain temporarily during migration, but remove the old `useFetch` and singleton caches in the final tree.

`resources.ts` builders return `Resource<T> = {url: string, tags: readonly ResourceTag[]}`. `useResource<T>(resource: Resource<T> | null)` is the one URL-backed hook and returns `{data: T|undefined, error: ApiError|null, loading, refreshing, refetch}`. The exact canonical URL is the cache key; tags travel explicitly with the descriptor, never via URL substring inference. Builders memoize stable descriptors or subscriptions key by URL, so recreating an equivalent descriptor during render does not resubscribe. Resource descriptor builders own encoded path segments and sorted query serialization; omit undefined values and preserve meaningful empty/false/zero. Every cache entry also has typed metadata (kind, ticketId/projectSlug) on the descriptor, so invalidation does not rely on substring matches. Disabled null performs no request/subscription. Different detail URLs never show another ticket's data. Keep last good data only for the SAME key during background refresh, with a visible error/retry; cross-key keepPrevious is intentionally not supported in this ticket: Sessions page/filter changes show a loading state until the new key resolves, rather than presenting previous-filter results as current. This is an accepted small presentation change, covered in browser tests; same-key refresh never blanks good data.

Store contract: one shared in-flight GET per key, reference-counted subscribers, immutable stable snapshots, generation counters and AbortController. Fetch starts on subscribe/effect, never during render. A last-unsubscribe abort invalidates the generation; remount and StrictMode subscribe/unsubscribe cycles can restart. Older responses cannot overwrite newer loads or another key. An invalidation DURING a request marks it dirty and schedules exactly one trailing refresh after settle, rather than losing the update by deduping it away. Stale inactive entries refresh when next subscribed; inactive entries expire after five minutes. Only reconnect after a known connection loss invalidates all active resources; the initial connected frame must not duplicate the initial GET. Track reconnecting→open in wsManager rather than invalidating on every connected message. Do not retry indefinitely or retry mutations automatically.

Use an instance-based `ResourceProvider` with a browser singleton client and isolated per-test/SSR clients. `getServerSnapshot` is stable seeded data or a stable loading snapshot; SSR never opens a socket, starts timers or fetches. Dispose releases all timers/requests/subscriptions. Only the first active client resource subscription attaches the central WS invalidator, and the last detaches it. Specialized chat/dispatch subscribers continue through the same existing wsManager connection, not new sockets.

`client.ts` is the only production location accessing global fetch. Export `requestJson`, `requestResponse` (preserves status/raw body for receipt protocol), and binary upload support; inject a fetch implementation for tests. Preserve API errors (`status`, `message`, body including `next`, dispatch warnings), JSON/204 semantics, headers, AbortSignal and FormData/Blob content type. Transport failure/malformed accepted responses for SV-11 must still mean unknown, never fabricate failed/not-accepted state.

`mutate(method,url,body,{invalidates})` uses client.ts, returns the actual response and invalidates explicit resource keys/tags after success. A lifecycle 200 with failed/unknown dispatch remains a successful move and still invalidates detail/board/inbox, while warnings remain visible. On uncertain write failure invalidate relevant reads without retrying the write. Keep existing domain methods such as `runTicketVerb`; they delegate to mutate and declare invalidations. Errors reach the existing UI error state, never unhandled rejected promises. Route every existing production raw fetch in pages/components/hooks/hotkeys/lib through this layer.

Exceptions are STATEFUL OWNERS, not raw-fetch loopholes: `useTicketChat` retains WS item reduction, paging and sequencing through chat-api; `StageDispatchController` retains exact-target POST, cancellation, generation and receipt polling semantics through injected requestResponse; uploads retain binary headers; finite chat bootstrap/paging may use imperative requests because their response merges into an ordered state machine. These do not maintain parallel generic resource caches. Search debounce chooses a null or canonical search resource. Config/template/view-pref singletons and finite Inbox/Events/Usage/Session/Project GETs move to useResource. Receipt timers must not be replaced by ordinary cache revalidation. Preserve all SV-11 regression tests when adapting injected fetch interfaces.
