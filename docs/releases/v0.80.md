# v0.80 — the terminal-launch stack is gone

An assignment is worked in the dashboard's **Chat** tab. The machinery Syntaur
used to reach an agent through a terminal — a `syntaur://` deep link, an
AppleScript applet, launch prompts, `AgentConfig` profiles, a transcript
scanner, a PTY daemon and a browser terminal — has been deleted, about 40 000
lines of it. See [assignment-chat.md](../assignment-chat.md) for what replaces
it.

**Back up `~/.syntaur/syntaur.db` before upgrading.** The sessions schema moves
to v11, which rebuilds the `sessions` table.

---

## One-time cleanup on an upgraded machine

None of this is done for you — Syntaur never touches installed system state on
upgrade. Each step is safe to skip; nothing below breaks if you leave it.

### 1. Remove the `syntaur://` URL handler

```bash
rm -rf /Applications/syntaur-url.app ~/Applications/syntaur-url.app
/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister \
  -u /Applications/syntaur-url.app
/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister \
  -u ~/Applications/syntaur-url.app
```

The bundle id was `app.syntaur.url-handler`. Nothing produces `syntaur://` links
any more, so a stale registration is inert — but it will keep claiming the
scheme until you unregister it.

### 2. Unload the session-scan LaunchAgent

```bash
launchctl bootout gui/$(id -u)/com.syntaur.session.scan
rm -f ~/Library/LaunchAgents/com.syntaur.session.scan.plist
```

The transcript scanner it ran is gone; the job now fails every five minutes with
"unknown command". `com.syntaur.schedule.tick` **stays** — see §5.

### 3. Delete the retired config blocks

Open `~/.syntaur/config.md` and remove:

- the whole `agents:` list (terminal-launch profiles — chat agents are files
  under `~/.syntaur/agents/<id>.md` now),
- the whole `agentDiscovery:` block,
- `terminal:` **only if** you never use `syntaur open` — that verb still reads
  it.

A leftover block is ignored, not an error.

### 4. Delete the syntaurd sockets

```bash
rm -rf ~/.syntaur/daemon ~/.syntaur/runtime/daemon
```

Nothing listens on them. If a `syntaurd` process is somehow still running, kill
it — no version of Syntaur will talk to it again.

### 5. Rewrite your schedules

**This one you must do, or your schedules stop firing.** A schedule used to open
a terminal with a launch prompt; it now posts a message into an assignment's
chat. The store refuses a pre-chat job by name rather than guessing a message
for it, so `syntaur schedule list` will print a line like:

```
syntaur: skipping schedule job-1234.md: Field `message` is missing — this is a
pre-chat schedule (it still has `promptTemplate`/`playbook`/`terminalPreference`).
Schedules now post a chat message; delete this job and recreate it with `--message`.
```

Delete each one and recreate it:

```bash
# before (v0.79)
syntaur schedule create --assignment my-task --agent claude \
  --prompt 'plan @assignment' --terminal ghostty --cron '0 3 * * *'

# after (v0.80)
syntaur schedule create --assignment my-task \
  --message 'Pick up the plan and implement the next task.' \
  --cron '0 3 * * *'
```

`--agent` is now optional and names a **chat** agent id (a file under
`~/.syntaur/agents/`); omit it and the assignment's default agent answers.
`--prompt`, `--playbook` and `--terminal` are gone.

Three behaviour changes worth knowing:

- The assignment must have an agent attached in its Chat tab. A schedule whose
  assignment has none records an error instead of firing.
- The launchd `com.syntaur.schedule.tick` job needs the **dashboard running** to
  dispatch, because it posts over the chat REST route. With the dashboard down
  it records an error on the schedule rather than opening a terminal. If you
  rely on unattended schedules, keep `syntaur dashboard` up.
- A `running` job is tracked by asking the chat where its message stands. When
  the chat cannot answer — the dashboard is down, the chat index was rebuilt, or
  the message id no longer resolves — that reads as "still running", because
  reaping a live job on a missing signal is worse than leaving one late. That
  grace is **bounded at two hours**: past it the job is marked `dispatch_failed`
  with `state_unknown` in its event log, so a job can never sit in `running`
  for ever. `syntaur schedule retry <id>` re-arms it.

### 6. Move from the plugin to the skill pack and settings hooks

1. `npm i -g syntaur@latest` (or `syntaur update`).
2. `syntaur hooks install` — writes three hook entries to `~/.claude/settings.json`; backup at `~/.syntaur/hooks.backup.json`.
3. Remove the plugin-era install: delete the `syntaur@<marketplace>` key from `enabledPlugins` in `~/.claude/settings.json`, delete `~/.claude/plugins/marketplaces/<name>/plugins/syntaur/`, and remove its entry from that marketplace's `.claude-plugin/marketplace.json`. Until this step, plugin hooks and settings hooks both fire (two stage blocks per prompt). To shorten the window, clear `enabledPlugins` first, then delete the files.
4. `npx skills add prong-horn/syntaur -g -a claude-code` (or `npx skills add <local clone> …` before the release is on GitHub).
5. Delete any retired skill directories under `~/.claude/skills/` (`grab-ticket`, `plan-ticket`, and the other retired names listed in [cli.md](../cli.md#retired-in-v080)).
6. Codex leftovers: `~/.codex/plugins/syntaur`, the `syntaur` entry in `~/.agents/plugins/marketplace.json`, and any `~/.codex/skills/*` syntaur copies.
7. The `integrations:` and `onboarding:` blocks in `~/.syntaur/config.md` are removed automatically by the first `syntaur` command after the upgrade — nothing to do.
8. `syntaur doctor` — expect `hooks.installed` PASS and `skills.installed` PASS when steps 2–4 are done.

SessionEnd is gone: closing a terminal no longer stops the session row. The dashboard maintenance loop sweeps idle `active` rows (default 6 h); to close one by hand, `printf '{"session_id":"<id>"}' | syntaur session stop --from-hook`; see [Hooks](../cli.md#hooks).

### 7. Strip the derived markdown and turn the home into a git repository

1. `syntaur migrate v2` (dry-run) — prints counts for the **`derived`** step: derived project files removed, record-file counters stripped, and `**Recorded:**` lines injected where needed.
2. `syntaur migrate v2 --apply` — applies `derived` (and any earlier pending steps) after the usual backup. Deletes `manifest.md`, `_index-*.md`, `_status.md`, and `resources/_index.md` / `memories/_index.md` when present; strips `entryCount`, `handoffCount`, `decisionCount`, and `updated` from legacy record frontmatter.
3. `syntaur init` — `git init` in the home when missing, `.gitignore`, `home-commit.sh`, and the daily auto-commit scheduler (`--no-auto-commit` to skip launchd/cron).
4. `syntaur doctor` — expect `project.derived-files-present` PASS on a migrated home, `git.home-repo` PASS after init, and `git.auto-commit` PASS when the scheduler is installed (WARN when only the script exists).
5. `syntaur history <id>` — git log scoped to the ticket folder; `syntaur history <id> --events` shows the SQLite audit table.

## Commands that no longer exist

`syntaur url`, `syntaur install-url-handler`, `syntaur agents *`, `syntaur tui`,
`syntaur daemon`, `syntaur bg`, `syntaur attach`, `syntaur attach-doctor`,
`syntaur pty-host`, `syntaur session scan`, `syntaur session scan-install`,
`syntaur session scan-uninstall`.

`syntaur browse` **stays** as a read-only project/assignment tree — Enter
expands a project and it no longer launches anything. `syntaur open` stays and
still opens a terminal at a worktree.

Also removed with the skill-pack install path: `setup`, `install-plugin`,
`install-codex-plugin`, `setup-adapter`, `uninstall`, `uninstall-skills`;
`install-statusline` / `configure-statusline` / `uninstall-statusline` (use
`syntaur statusline install|configure|uninstall`); the sixteen legacy protocol
skills (replaced by `syntaur-protocol`, `grab`, `plan`, `done`, `log`,
`worktree`).

## What else changed

- **Derived project markdown removed** — no more `manifest.md`, `_index-*.md`, `_status.md`, or resource/memory index stubs; rollups and graphs are computed at read time. Legacy record files no longer carry per-file counters (`entryCount`, `handoffCount`, `decisionCount`, `updated`).
- **Git-backed home** — `syntaur init` initialises `~/.syntaur` as a git repo with a daily `home-commit.sh` auto-commit; `syntaur history <id>` shows commits that touched a ticket folder.
- **No browser terminal.** The session detail page shows the session's facts,
  its usage rollup and a link to the assignment's Chat tab.
- **Codex terminal sessions are no longer discovered.** The scanner was the only
  thing that found transcripts for agents without hooks. Tracked sessions are
  now Claude Code terminals (hooks), chat sessions (the broker) and anything
  registered with `syntaur track-session`. The usage collector is unaffected —
  it reads the transcripts itself.
- **Session liveness is `status === 'active'`**, plus a time-based sweep: an
  `active`, non-chat row idle longer than `session.idleSweepHours` (default 6)
  is marked `stopped` and its open engagement closed with reason `stale-sweep`.
  There is no more `lsof`, no pid probing and no `claude agents --json` join.
- **Schema v11.** `launch_reservations` is dropped, and `sessions` loses `pid`,
  `pid_started_at` and `activity`. `transcript_path` is kept — the session
  summarizer needs it. Historical `hosted_by` values other than `acp` are set to
  NULL.
- **Codex chat spend is priced.** The OpenAI GPT-5.x list rates are in
  `MODEL_PRICING`, so a codex chat turn no longer books at $0.
- **Chat schema v4** adds `chat_harness_options` — per-harness cached adapter
  `configOptions` and auth state for the Agents editor model/effort pickers — and
  `chat_sessions.standing_fingerprint`, a sha256 of the roster lines and system
  prompt last sent as standing context so a dashboard restart can re-send the
  block when a definition or participant roster changes.
- **Agent `permissions: auto`.** Syntaur can answer every permission request
  without a card; the permission card also has **Allow all this session**.
- **`node-pty` and `@xterm/*` are gone**, and so is the `postinstall` script —
  `npm i -g syntaur` no longer compiles or patches a native module.
