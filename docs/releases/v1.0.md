# v1.0 — the v2 protocol

Syntaur 1.0.1 is the v2 ticket protocol shipped as a single product: one noun (**ticket**), template manifests with explicit stages, lifecycle verbs that move `status` and evaluate gates, a typed **journal** (`syntaur log`), a git-backed home (`syntaur init`, `syntaur history`), six protocol skills and three Claude Code hooks, and dashboard **Chat** (ACP) as the way agents work a ticket. Terminal launch, plugins, todos, schedules, and derived project markdown are gone.

**History:** npm releases **0.80.0** and **0.80.1** (August 2026) were the last cut of the pre-v2 line. The **1.0.0** tag never reached npm: its release run failed on a test-environment dependency (the chat broker tests needed the adapter binary on PATH), fixed forward as **1.0.1** with no product change. They added the per-session **input/output token split** on the Sessions page (kept in 1.0) and pinned CI to Node 24.18.0. Everything else in this note ships in **1.0.1**.

## Upgrade an existing machine

Do this on a machine that already has a v1-layout home (`assignments/`, derived indexes, plugin-era hooks). Read the dry-run output before every `--apply`.

**0. Stop the dashboard.** Back up the whole home:

```bash
tar czf ~/.syntaur.bak-1.0-$(date -u +%Y%m%dT%H%M%SZ).tgz -C ~ .syntaur
```

**1. Install the release CLI:**

```bash
npm i -g syntaur@1.0.1
# or: syntaur update
```

**2. Structural v2 migration:**

```bash
syntaur migrate v2          # dry-run — read derived: counts
syntaur migrate v2 --apply  # writes ~/.syntaur.bak-v2-<ts> beside the home first
```

The `derived` step deletes derived project files (`manifest.md`, `_index-*.md`, `_status.md`, resource/memory index stubs), strips `entryCount`, `handoffCount`, `decisionCount`, and `updated` from legacy record frontmatter, and injects `**Recorded:**` lines on undated decision/handoff blocks before the strip. Earlier steps rename `assignments/` → `tickets/`, assign ids, set `template: legacy`, map statuses, and re-key SQLite.

**3. Per project — merge legacy record files into `journal.md`:**

```bash
syntaur migrate journal --project <slug> --all        # dry-run
syntaur migrate journal --project <slug> --all --apply
```

Each ticket gets a `.migrate-journal.bak/` during apply; legacy sidecars are removed after a successful merge. Default target template is `feature`.

**4. Reset a drifted built-in manifest (optional but recommended if you customised `legacy`):**

```bash
syntaur template reset legacy
```

**5. Move retired home entries out of the live tree** (into the tarball directory or `retired/`), for example:

`servers/`, `todos/`, `schedules/`, `workspaces.json`, `saved-views.json`, `tier3-violations.log`, `syntaur.db.*.bak`, and any project-level `todos/`.

**6. Git-backed home:**

```bash
syntaur init    # git init, .gitignore, identity, initial commit, home-commit.sh, daily scheduler
# syntaur init --no-auto-commit   # skip LaunchAgent/cron
```

**7. Skills and hooks:**

```bash
npx skills add prong-horn/syntaur -g -a claude-code -y
syntaur hooks install
```

Remove the old marketplace plugin (`enabledPlugins`, `~/.claude/plugins/.../syntaur/`, marketplace entry). Delete retired skill dirs under `~/.claude/skills/` (`grab-ticket`, `plan-ticket`, … — see [cli.md](../cli.md#retired-in-v10)). Clear Codex leftovers (`~/.codex/plugins/syntaur`, `~/.agents/plugins/marketplace.json` syntaur entry, stale `~/.codex/skills/*` copies).

**8. Verify:**

```bash
syntaur dashboard
syntaur doctor
```

**Clean** means no `error` results and no `warn` in `env`, `structure`, `project`, `git`, `hooks`, `skills`, or `dashboard`. Ticket-content warnings (empty objective, legacy companion files) are yours to fix; `project.derived-files-present` should pass after step 2.

**Rollback:** restore the full tarball (`rm -rf ~/.syntaur && tar xzf <tgz> -C ~`), or for the `derived` step alone restore the `~/.syntaur.bak-v2-*` copy next to the home.

## 1. Remove the `syntaur://` URL handler

```bash
rm -rf /Applications/syntaur-url.app ~/Applications/syntaur-url.app
/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister \
  -u /Applications/syntaur-url.app 2>/dev/null || true
/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister \
  -u ~/Applications/syntaur-url.app 2>/dev/null || true
```

Nothing produces `syntaur://` links after 1.0.

## 2. Unload the session-scan LaunchAgent

```bash
launchctl bootout gui/$(id -u)/com.syntaur.session.scan 2>/dev/null || true
rm -f ~/Library/LaunchAgents/com.syntaur.session.scan.plist
```

The transcript scanner is gone. `com.syntaur.home-commit` from `syntaur init` is separate and should remain when you use auto-commit.

## 3. Delete retired config blocks

In `~/.syntaur/config.md`, remove if still present:

- the whole `agents:` list (terminal-launch profiles),
- the whole `agentDiscovery:` block,
- `integrations:` / `onboarding:` (removed on first CLI run after upgrade),

Chat agents live in `~/.syntaur/agents/<id>.md` ([ticket-chat.md](../ticket-chat.md)). Optional `terminal:` stays if you use `syntaur open --terminal`.

## 4. Delete the syntaurd sockets

```bash
rm -rf ~/.syntaur/daemon ~/.syntaur/runtime/daemon
```

No process listens on them.

## 5. Retired ops folders

The **schedules** subsystem is deleted in v2. Remove `~/.syntaur/schedules/` (and unload any `com.syntaur.schedule.tick` LaunchAgent if you still have one). Do not recreate schedule jobs — use dashboard chat or external cron outside Syntaur.

Move `servers/`, `todos/`, `workspaces.json`, and `saved-views.json` out of the home (step 5 in the upgrade guide).

## 6. Move from the plugin to the skill pack and settings hooks

1. `npm i -g syntaur@1.0.1` (or `syntaur update`).
2. `syntaur hooks install` — three hook entries in `~/.claude/settings.json`; backup at `~/.syntaur/hooks.backup.json`.
3. Remove the plugin-era install (see upgrade step 7).
4. `npx skills add prong-horn/syntaur -g -a claude-code -y`.
5. `syntaur doctor` — expect `hooks.installed` and `skills.installed` PASS.

SessionEnd is gone. Close a session manually: `printf '{"session_id":"<id>"}' | syntaur session stop --from-hook`. Otherwise the dashboard sweeps idle `active` rows past `session.idleSweepHours` (default 6 h). See [Hooks](../cli.md#hooks).

## 7. Derived markdown and git history

Covered by `syntaur migrate v2 --apply` (`derived` step) and `syntaur init` in the upgrade guide. Afterward: `syntaur history <id>` for git log on the ticket folder; `syntaur history <id> --events` or `syntaur timeline <id>` for the SQLite audit table.

`syntaur url`, `syntaur install-url-handler`, `syntaur agents *`, `syntaur tui`,
`syntaur daemon`, `syntaur bg`, `syntaur attach`, `syntaur attach-doctor`,
`syntaur pty-host`, `syntaur session scan`, `syntaur session scan-install`,
`syntaur session scan-uninstall`, `syntaur browse`, `syntaur schedule *`,
`syntaur migrate-events`, `syntaur status *`, `syntaur complete`, `syntaur fail`,
`syntaur fact set`, `syntaur attest`, `syntaur setup`, `install-plugin`,
`install-codex-plugin`, `setup-adapter`, top-level `uninstall` subcommand,
`uninstall-skills`, `install-statusline` / `configure-statusline` /
`uninstall-statusline` (use `syntaur statusline *`), and the sixteen legacy protocol
skills (replaced by `syntaur-protocol`, `grab`, `plan`, `done`, `log`, `worktree`).

**Still available:** `syntaur open` (worktree path, optional terminal/editor),
`syntaur dashboard`, lifecycle verbs in [cli.md](../cli.md#lifecycle-verbs), and
`syntaur hooks` / `syntaur statusline`.

## What else changed

- **v2 ticket protocol** — `ticket.md` + `chat/` kernel; template manifests; ids `<PREFIX>-<n>`; `blocked` / `parked` flags; `syntaur show` as the agent guide.
- **Derived project markdown removed** — rollups are computed at read time; `migrate v2` deletes index stubs and strips record counters.
- **Git-backed home** — `syntaur init`, `home-commit.sh`, `syntaur history <id>`.
- **No browser terminal** — session detail links to ticket Chat; ACP adapters only.
- **No Codex transcript scanner** — tracked sessions: hooks, chat broker, `syntaur track-session`.
- **Session liveness** — `status === 'active'` plus idle sweep; no pid probing.
- **Schema** — ops tables dropped; `sessions` slimmed; chat schema v5 (`ticket_id`, `session_key` `<ID>~<harness>`).
- **Codex chat spend priced** — GPT-5.x list rates in `MODEL_PRICING`.
- **Chat schema v4+** — `chat_harness_options`, `standing_fingerprint` on `chat_sessions`.
- **Agent `permissions: auto`** and **Allow all this session** on permission cards.
- **`node-pty` and `@xterm/*` removed** — no native postinstall compile.
